# Figure captions

## Performance

**Measured move-attempt throughput in two controlled comparisons.** Bars show the median rate; points show all three paired timing runs, with thin lines connecting matched records. **a,** RASPA3 3.1.0 and the OpenGCMC native cached CPU sampler: 40,000 production conventional insertion/deletion attempts after 10,000 warm-up attempts on the same macOS system. **b,** gRASPA and the OpenGCMC native cached CPU sampler: 1,000 scheduled insertion/deletion attempts from an empty state, without warm-up, on the same WSL system. gRASPA used synchronized CUDA launches (`CUDA_LAUNCH_BLOCKING=1`) on a shared GPU, at 81–82 °C. Median paired rate ratios are **21.60×** (observed range 20.06–23.27×) and **30.17×** (28.34–30.25×). Both comparisons use one trial per insertion, a neutral shifted-LJ probe (σ = 3 Å; ε/kB = 5 K) in the same 4,992-site Cu-BTC geometry, a 12 Å cutoff, nominal temperature 300 K, and activity 3/V. Setup and final energy checks are outside the timers; reference programs retain their native production statistics and OpenGCMC records molecule count every 20 attempts. Pairing denotes matched protocol and seed identifier rather than identical random trajectories. The panels use independent scales. These are protocol-specific attempt-rate comparisons; equilibrium ESS is a separate quantity. Full inputs, raw logs and timing definitions are linked in [the benchmark documentation](../docs/benchmarks.md).

## Architecture

**Reusable representations and exact sampling in OpenGCMC.** **a,** Periodic host geometry is represented by exact fractional-cell CSR candidate plans and bound mixed-parameter rows. Independent chains share immutable host data and own their guest state and random generator. An optional frozen full-support voxel alias proposal supplies nonuniform root positions. Lattices, sparse strips, parameter tables, candidate conformations, voxel maps and weight glyphs illustrate the implemented data structures and operations. Coral denotes trial growth, teal exact caches and energies, purple optional proposals and CBMC weighting, green accepted-state reuse, and blue execution routes. **b,** Batched exact energies supply forward and retraced CBMC weights. The nonuniform proposal is corrected by 1/[Vq(r)] in both directions. The accepted-state guest environment is reused after rejection and invalidated after an accepted change, then rebuilt on its next query. Index exclusion removes the moved molecule from its own environment. **c,** The C++ native CPU route illustrates single-component short-range LJ/DSF sampling. The sampler also provides [native long-range sampling](../docs/long_range.md). The Python general route supports mixtures, Ewald electrostatics, and optional delayed acceptance with exact target correction. Its optional CUDA route evaluates energies with resident tables and reusable workspaces. Dashed arrows denote optional routes; the MC loop is not represented as GPU resident. The performance comparisons use conventional single-site K = 1 moves and do not isolate the speed contribution of each architecture module.
