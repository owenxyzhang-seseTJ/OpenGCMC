# OpenGCMC 计算升级与验证

## 实现范围

| 模块 | 已实现 |
|---|---|
| 巨正则采样 | 原生 C++ 多组分刚体及树状柔性 CBMC，支持按组分试探数及选择权重。用相同前缀进行柔性后缀生长与回溯。实现同温、同哈密顿量化学势副本交换，样本按热力学标签归属。 |
| CPU 内核 | 接受态客体周期分箱局部更新。保留可选重建路径用于配对。PME 的稀疏电荷改变量可跨若干接受移动合并，完整保存未刷新网格状态。 |
| 框架场缓存 | LJ 场和单位电荷电势独立键控，兼容工况共享原始场。并发构建锁、原子发布、损坏回建及缓存统计均已接入。 |
| GPU 内核 | 实现可选的 `cuda-resident`。迟滞校正只回传标量倒空间能量，接受后在设备提交结构因子增量。用 CPU 插件替身检查了提交及重启。 |
| 任务执行 | MCP stdio、持久化本地多链与 Slurm 数组适配。等温线和占据自由能窗口可以执行同一套分块与续跑流程。支持已完成块去重、取消、恢复及回执丢失对账。 |
| 化学模型 | 提供矩阵零和子空间电极求解和能量残差界，以及由给定空框架自由能与巨配分函数计算的渗透系综相权重。用稠密电极与解析双相权重核对。 |

## 内核与端到端时间

同一台 Apple M5 macOS 工作站。本表每个内核工况做 5 次配对，报告时间比中位数。MFI 做 8 个配对种子，报告从构建求解器到固定预算运行完毕的墙钟比。

| 工况 | 候选与基线 | 测得结果 |
|---|---|---:|
| 固定 384 个 LJ 客体，平移负载 | 客体分箱局部更新对整套重建 | 26.47× |
| 32³ PME 带电二聚体 | 最多积累 8 次已接受电荷变化对逐接受刷新 | 4.02× |
| MFI 二元体系，0.2 bar | 原生两阶段网格 CBMC 加局部更新对直接目标能量加重建 | 4.99× |
| MFI 二元体系，1 bar | 同上 | 4.78× |
| MFI 二元体系，5 bar | 同上 | 4.82× |

LJ 的 8、96、384 客体结果分别为 3.20×、12.20× 和 26.47×。MFI 的主要成本来自框架与长程能量。在这三个工况中，单独替换客体索引的墙钟比为 0.99–1.04×。32³ PME 配对的 5 组计数轨迹相同，能量最大绝对差为 7.28×10⁻¹² K。该微基准中 FFT 次数约降至原来的八分之一。MFI 的框架与模型准备时间首次为 0.246 s，随后热加载中位数为 0.060 s。[CPU 内核原始结果](cpu_kernels_m5.json) · [72 条 MFI 固定预算轨迹摘要](mfi_fixed_budget.json)

## CO₂/CH₄ 等温线与选择性

298 K，等摩尔气相，理想逸度系数。晶体来自 IZA 的全硅 MFI，使用 `1×1×2` 超胞、明确的 LJ 参数和带部分电荷的 CO₂ 客体。吸附量为分子数/超胞。选择性定义为两组分平均吸附量之比除以气相摩尔分数比。结果对应文档所列的受控有限 Ewald 模型。[IZA 原始 CIF](https://www.iza-structure.org/IZA-SC/cif/MFI.cif) · [模型、力场和复现条件](../inputs/mfi/README.md)

单压力固定预算对照中，0.2 bar 的两种主要路径都达到诊断门槛。1 和 5 bar 的部分观测量仍需更长采样。随后化学势交换确认计算采用 8 套独立梯队，每套 11 个压力点，预热 100 轮、生产 900 轮，每轮每个压力点尝试 1,200 次移动。四个本地工作线程用时 143.46 s，记录 97 次梯队端点往返。11 个点均达到计数 MCSE ≤ 0.20、对数选择性 MCSE ≤ 0.10 和秩归一化 $\hat R$ < 1.01 的预设门槛。固定预算两阶段的加速倍数与交换计算的收敛证据分别取自各自对照。[化学势交换先导](mfi_exchange_pilot.json) · [独立确认轨迹统计](mfi_exchange_confirmation.json)

## 调度与验证边界

MCP 实际 stdio 调用用 4 个本地工作线程执行了 MFI 的 3 个压力点。12 条链全部完成，共发布 24 个样本块。从持久登记到最后一块提交用时 4.53 s。4 个原始场各构建一次，其余 92 次场请求使用缓存。重复提交获得同一个 `run_id`。该运行验证执行与缓存共享，吸附等温线取上面的长链确认数据。[本地 MCP 运行与产物索引](dispatch_m5.json)

完整测试集通过 275 项测试、28 项子测试。macOS 跳过一项 Linux 文件大小限制测试。故障注入覆盖 32 条链、96 个提交块的过期租约、取消与恢复，也覆盖 Slurm 作业已提交但回执丢失。CUDA 算法路径经过 CPU 插件接口与等能重启核对。CPU 补充验证已在HPC Intel 节点完成，包括真实 Slurm 数组执行和与 M5 本地 MCP 的逐样本核对。GPU 跨链同批内核与 MCP Draft Tasks 扩展仍处于规划阶段，当前入口采用设备单链驻留和领域 `run_id`。分数分子插入、20 基础场和 Ewald 可证明余项剪枝仍处于规划中的判别阶段。[原生数值回归](../../tests/test_upgrade_sampling.py) · [MCP 与 Slurm 故障测试](../../tests/test_scheduling.py) · [M5 与HPC CPU 补充验证](paired/README.md)
